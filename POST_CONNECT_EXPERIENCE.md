# UiPath Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
RPA-разработчик/оператор роботизированных процессов в компании, использующей UiPath
Orchestrator для управления парком программных роботов.

## 2. Момент истины после подключения
Сразу после `connect_uipath` — сводка по флоту роботов и очередям: сколько роботов
онлайн/офлайн, сколько заданий в очереди ждут выполнения, сколько упало за последний
период.

## 3. Что пользователь видит
- Роботов (машины/сессии) с их статусом — `list_robots`.
- Процессы (опубликованные пакеты автоматизации) — `list_processes`.
- Задания (jobs) с статусом выполнения — `list_jobs`, `get_job`.
- Очереди (queues) и элементы в них — `list_queues`, `list_queue_items`.
- Логи выполнения конкретного задания — `get_job_logs`.
- Расписания запуска процессов — `list_schedules`.
- Активы (assets — переменные/креды для роботов, без значений секретных) —
  `list_assets`.

## 4. Чем пользователь может управлять
- Запускать процесс на конкретном роботе/группе роботов — `start_job`.
- Останавливать/приостанавливать выполняющееся задание — `stop_job`, `pause_job`.
- Добавлять элемент в очередь для обработки роботом — `add_queue_item`.
- Повторно обрабатывать элемент очереди, упавший с ошибкой — `retry_queue_item`.
- Публиковать новую версию процесса — `publish_process`.
- Создавать/менять расписание автозапуска — `create_schedule`.
- Устанавливать значение актива (не-секретного) — `set_asset_value`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'сколько заданий сейчас в очереди на обработку счетов и какие
упали с ошибкой?'. Она находит через `list_queue_items`, а я прошу повторить неудачные —
`retry_queue_item` ставит их обратно в очередь без захода в Orchestrator."

## 6. Что делает это "заточенным под него"
`list_queues` работает с РЕАЛЬНЫМИ очередями, которые компания сама назвала под свои
процессы (например "Invoice_Processing", "HR_Onboarding") — Webbee оперирует их языком.
